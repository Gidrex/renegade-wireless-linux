# Разработка

Как устроен проект, что известно о протоколе и как его развивать.

## Структура

```
src/
  device.rs        транспорт: поиск hidraw, пакеты 0x08/0x09, чтение/запись памяти, ожидание сна мыши
  config.rs        карта памяти, контрольные суммы, DPI-таблицы сенсоров, кнопки и клавиши
  macros.rs        формат макросов: кодирование, разбор и текстовый синтаксис событий
  mouse.rs         State (всё, что читается с мыши) и сеттеры set_*: общий слой для CLI и GUI
  main.rs          CLI renegade: разбор аргументов и вывод show
  bin/renegade-gui/main.rs          GUI на egui/eframe: вкладки, модель, фоновый поток
  bin/renegade-gui/macro_editor.rs  вкладка «Макросы»: библиотека, запись, таблица событий
assets/fonts/      Geologica Regular/SemiBold (статические срезы, OFL)
70-renegade.rules  правило udev
```

Слои зависят только сверху вниз: `device` ← `config`/`macros` ← `mouse` ← CLI/GUI. В CLI и GUI нет знаний о байтах: всё кодирование лежит в `config.rs` и `macros.rs`, а запись — в `mouse.rs`.

### GUI

- Обмен с мышью идёт в фоновом потоке (`Worker`): мышь может спать до 30 с, а интерфейс при этом не должен замирать. Задача — замыкание `FnOnce(&mut Device) -> Res<Option<State>>`. Если она вернула `State`, интерфейс обновляется.
- Интерфейс редактирует `Model`, копию прочитанного состояния. Кнопка «Применить» сравнивает `Model` с исходной копией и вызывает сеттеры `mouse::set_*` только для изменившихся секций, затем перечитывает мышь.
- Кнопки и макросы хранятся в текстовом синтаксисе CLI (`key:ctrl+c`, `click:50:2`, события макроса). Поэтому разбор, проверка и запись в GUI и CLI — один и тот же код.
- Тема и шрифт задаются в `setup_style`. Geologica лежит в `assets/fonts` в виде статических Regular и SemiBold, нарезанных из вариативного файла Google Fonts. По умолчанию вариативный файл даёт начертание Thin, а egui не умеет выбирать оси.

- Вкладка «Макросы» (`macro_editor.rs`) пишет только в `Model`: «Назначить на кнопку» меняет кнопку в модели, а в мышь всё попадает через общее «Применить». Запись забирает события клавиатуры в начале кадра (`capture`), до того как их увидят виджеты. Используется `physical_key`, поэтому раскладка не важна. Кнопки мыши записываются только щелчками над областью записи, чтобы не ловить клики по самому интерфейсу.
- Библиотека макросов — файлы `~/.config/renegade/macros/<имя>.txt` с токенами CLI. CLI читает их через `macro N R @файл`.

**Правило: у CLI и GUI одинаковый набор функций.** Новая возможность добавляется в оба.

### Нумерация кнопок

Пользователь видит кнопки 1–8, как на схеме мыши в OemDrv. В памяти они лежат в других слотах — `BUTTON_SLOTS` в `config.rs`:

| Кнопка | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| Слот (с 0) | 0 | 1 | 2 | 4 | 3 | 8 | 10 | 11 |

Остальные слоты физических кнопок не имеют, утилита их не трогает.

## Протокол

Приёмник `25a7:fa4a` (или `fa4b`), интерфейс 1, коллекция с usage page `0xFF02`.

- **Запрос:** feature-репорт `0x08`, 17 байт: `[08, cmd, payload…, cks]`.
- **Ответ:** input-репорт `0x09` той же формы.
- **Контрольная сумма:** все 17 байт в сумме дают `0x55` (mod 256).

| cmd | Что делает |
|---|---|
| `0x07` | запись памяти: `[00, addr_hi, addr_lo, len≤10, data…]`. Ответ: `[09 07 status addr_hi addr_lo len]`, status 0 — успех |
| `0x08` | чтение памяти, тот же payload без data. Ответ: `[09 08 status addr_hi addr_lo len data…]` |
| `0x01` | «рукопожатие» Windows-программы: 4 случайных байта и проверка ответа. Для работы не нужно |
| `0x02` | TellDrvStatus (1 — программа открыта). Не используем |
| `0x03` | статус соединения. Отвечает приёмник, даже если мышь спит |
| `0x04` | неизвестно, отвечает `… 02 05`. Возможно, батарея |
| `0x09` | шлётся после сброса настроек. Не используем |

Чтение и запись доходят до мыши по радио. Спящая мышь не отвечает, пока её не подвинуть. Ответ может опоздать, поэтому `device.rs` перед каждой командой выбрасывает старые ответы и сверяет адрес в ответе.

### Карта памяти

У каждого поля есть контрольный байт: однобайтовое значение хранится как `[v, 0x55-v]`, трёхбайтовое — как `[a, b, c, 0x55-a-b-c]`.

| Адрес | Формат | Что |
|---|---|---|
| `0x00` | `[code, cks]` | частота опроса: 1=1000, 2=500, 4=250, 8=125 Гц |
| `0x02` | `[n, cks]` | число уровней DPI в цикле |
| `0x04` | `[i, cks]` | текущий уровень, ведёт сама мышь |
| `0x0C` | 8 × `[x, y, high, cks]` | уровни DPI, коды сенсора (таблицы в `config.rs`) |
| `0x2C` | 8 × `[r, g, b, cks]` | цвета уровней |
| `0x4C` | `[mode,c, bright,c, speed,c]` | логотип: 0 выкл, 1, 2. Яркость — код из таблицы 10 уровней |
| `0x54` | `[r,g,b,c, mode,c, bright,c]` | DPI-индикатор: 0 выкл, 1, 2, 3 |
| `0x5C` | `[speed, cks]` | скорость DPI-индикатора, пишется только для режимов 2 и 3 |
| `0x60` | 16 × `[type, a, b, cks]` | кнопки (ниже) |
| `0xA0` | 7 байт | «основная» подсветка. У этой модели выключена (`ShowMainEffect=0`), не трогаем |
| `0x100 + slot·0x20` | блоб | нажатия клавиш для кнопки типа 5 |
| `0x300 + slot·0x180` | макрос | область макроса кнопки |

**Кнопки** `[type, a, b]`:

| type | Значение |
|---|---|
| 0 | отключена |
| 1 | кнопка мыши, `a` = маска: 1 левая, 2 правая, 4 средняя, 8 назад, 0x10 вперёд |
| 2 | DPI: `a` = 1 по кругу, 2 плюс, 3 минус |
| 4 | серия кликов: `a` — интервал, `b` — число кликов (двойной клик = 50,2) |
| 5 | клавиши, блоб по адресу `0x100 + slot·0x20` |
| 6 | макрос, `a` = slot, `b` = повтор (1–253 раз, `0xFF` пока нажата, `0xFE` до нажатия любой) |
| 7, 8, 9 | спец-функции Windows-программы (огонь, sniper, переключение подсветки — какая из них какая, не выяснено). Доступны как `raw:` |

**Блоб клавиш:** `[n, (op, code, 0)×n, cks]`, сумма блоба равна `0x55`.

| op | Действие |
|---|---|
| `0x80` | модификатор нажат (маска 1 ctrl, 2 shift, 4 alt, 8 win) |
| `0x81` | клавиша нажата (HID usage) |
| `0x40` | модификатор отпущен |
| `0x41` | клавиша отпущена |

**Макрос** (0x180 байт):

- `[0]` — длина имени в байтах; `[1..31]` — имя в UTF-16LE, не больше 15 символов (длиннее OemDrv обрезает). Имя видно в OemDrv; мы его пишем и читаем так же (`encode(events, name)` / `decode_name`).
- `[0x1F]` — число событий.
- События по 5 байт: `[op|kind, code, 0, delay_hi, delay_lo]`.
  - op: `0x80` нажатие, `0x40` отпускание.
  - kind: 0 модификатор (биты HID, правые — `0x10/0x20/0x40`), 1 клавиша, 4 кнопка мыши.
  - Задержка — после события, в мс, минимум 3.
- Затем `cks` и 3 нулевых байта. Контрольная сумма считается от `[0x1F]` до последнего события, имя в неё не входит.

**Сенсор** определяется по `bcdDevice >> 12` приёмника: 0 — PAW3325, 1 — PAW3335, 2 — PAW3330 (не поддержан). У PAW3325 значения выше 5000 DPI кодируются как код от `dpi/2` с флагом `high=1`.

## Откуда это известно

Установщик — Inno Setup, распаковывается `innoextract`. Программа — `OemDrv.exe` (MFC, MSVC), HID-обёртка — `Lowerdev.dll` (`SetFeature`/`GetFeature`…). Дизассемблер: `objdump -d -M intel OemDrv.exe`. Ключевые функции (VA):

| Адрес | Что |
|---|---|
| `0x441340` | контрольная сумма пакета |
| `0x4421d0` | отправка 17-байтовой команды |
| `0x441390` | SendCMD(cmd, data) |
| `0x4414f0` | рукопожатие cmd 1 |
| `0x441900` | WriteEEPROM(addr, data, len), куски по 10 байт |
| `0x441b80`, `0x441c20` | ReadEEPROM |
| `0x441e90`, `0x441d60`, `0x4420a0` | запись DPI, цветов, таблицы кнопок |
| `0x438470` | DPI → код сенсора |
| `0x438100–0x4383a0` | инициализация таблиц DPI; данные `0x5cb1b8/0x5cb410` (3325), `0x5cbc70/0x5cbef0` (3335), шаг 4 байта |
| `0x440eee` | выбор сенсора по номеру версии |
| `0x40b3b0–0x40be2f` | «Применить»: запись всего, включая подсветку и частоту |
| `0x40a630` | разбор подсветки из памяти |
| `0x40a8e0` | функция кнопки → `[type, a, b]` |
| `0x40ab70` | блоб клавиш |
| `0x40b070` | кодирование макроса; таблица адресов макросов `0x5cc810` |

Отладочные строки (`SendCMD`, `ReadROM Failed`, `WriteEEPROM`) лежат около `0x5a4b48` и помогают найти нужный код.

### Как посмотреть на оригинал

OemDrv запускается в Wine, если пробросить ему приёмник через hidraw. Без мыши программа сразу закрывается. Порядок такой:

1. Отдельный префикс, без Mono и Gecko: `WINEDLLOVERRIDES="mscoree,mshtml="`.
2. Установка: `wine setup.exe /VERYSILENT /SUPPRESSMSGBOXES '/DIR=C:\Renegade'`.
3. В реестре префикса включить hidraw:

   ```
   HKLM\System\CurrentControlSet\Services\winebus  EnableHidraw=1
   HKLM\System\CurrentControlSet\Services\winebus\Devices\VID_25A7&PID_FA4A  Hidraw=1
   ```

4. Без этого `winebus` игнорирует приёмник: у его интерфейса 1 первая коллекция клавиатурная. Проверить проброс: `WINEDEBUG=+hid`, в логе должно быть `creating hidraw device 25a7:fa4a`.
5. Программа живёт в трее, поэтому запускать в виртуальном рабочем столе с панелью: `wine explorer /desktop=Name,1280x860 'C:\Renegade\OemDrv.exe'` и `HKCU\Software\Wine\Explorer\Desktops\Name EnableShell=1`.

Под niri xdotool не может кликать в окна XWayland, а `import -window` может отдать устаревший кадр. Надёжнее снимать монитор через `grim -o <выход>`. После сеанса с оригиналом сверьте память мыши с бэкапом: программа может что-то записать.

## Как добавить функцию

1. **Байты.** Константы адресов и кодирование — в `config.rs` (или в отдельный модуль, как `macros.rs`). Сюда же юнит-тест на реальном дампе.
2. **Слой мыши.** Чтение — метод `State` в `mouse.rs`, запись — функция `set_*` там же. Сеттер проверяет значения и пишет только своё поле.
3. **CLI.** Команда в `main.rs` (`run` и `USAGE`), вывод — в `show`.
4. **GUI.** Поле в `Model`, `from_state`, сравнение и вызов сеттера в `write_changes`, редактор на нужной вкладке.
5. **Документация.** README (таблица возможностей и примеры) и этот файл (карта памяти).

## Проверки

```sh
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test
```

Юнит-тесты работают на байтах, считанных с настоящей мыши (`DUMP` в `config.rs`, `LKM` в `macros.rs`), и проверяют кодирование в обе стороны.

### Проверка на железе

Порядок проверки любой записи:

```sh
renegade backup before.bin          # 1. полный снимок
renegade <изменение> && renegade show   # 2. запись и обратное чтение (write_mem сам сверяет записанное)
renegade restore before.bin         # 3. откат
renegade backup after.bin && cmp before.bin after.bin   # 4. память совпадает байт в байт
```

Во время проверки мышь нужно шевелить, иначе она уснёт. Байт `0x04` (текущий уровень DPI) может отличаться, если нажимали кнопку DPI.

## Релиз

1. Поднять `version` в `Cargo.toml` и закоммитить.
2. `git tag vX.Y.Z && git push origin vX.Y.Z`.
3. Workflow `Release` прогонит тесты, соберёт `renegade` и `renegade-gui` на Ubuntu 22.04 и выложит архив с SHA256 в GitHub Releases.

CI (`ci.yml`) на каждый push и pull request гоняет fmt, clippy и тесты.

## Что не выяснено

- Батарея: OemDrv показывает её (при 50 % на нашей мыши). Возможно, это ответ на `cmd 0x04`: он приходил как `09 04 00 00 00 02 05`, и `05` может означать 50 %. Второй вариант — input-репорт `0x02`.
- Мультимедиа-клавиши (типы 3/4 в Windows-программе тоже кодируются как type 5, но с другим блобом).
- Точный смысл типов кнопок 7/8/9 и параметров `speed` подсветки.
- Начинается ли номер текущего уровня DPI (`0x04`) с 0 или с 1.
